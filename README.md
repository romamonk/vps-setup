# vps-setup

Воспроизводимая настройка VPS для удалённой разработки через SSH и tmux,
работы Claude Code и вспомогательных сервисов.

## Статус

Подготовлена базовая структура репозитория. Ansible playbooks и роли пока
не реализованы; настройки из примеров не применяют изменения к VPS.
Техническое задание: [VPS_CLAUDE_CODE_BOOTSTRAP_SPEC.md](VPS_CLAUDE_CODE_BOOTSTRAP_SPEC.md).

Исходная целевая ОС — Ubuntu Server 24.04 LTS. Планируется отдельный пользователь
`admin` с sudo и пользователь `agent` без sudo и доступа к системному Docker.

## Структура

- `inventories/example/` — пример inventory и параметров без реальных адресов и ключей.
- `inventories/local/` — локальный inventory (исключён из Git).
- `playbooks/` — будущие точки входа bootstrap, configure и docker.
- `roles/` — будущие Ansible-роли.
- `templates/` — шаблоны клиентских конфигураций.
- `examples/` — место для примеров вспомогательных сервисов.
- `tests/` — план проверок перед применением.
- `SECURITY.md` — границы безопасности и правила работы с секретами.

## Подготовка inventory

```sh
cp -R inventories/example inventories/local
```

Заполнить адрес VPS, исходного SSH-пользователя, публичные SSH-ключи и разрешённые
CIDR в локальной копии. Пример намеренно содержит незаполненные значения.
Private keys, токены и пароли в inventory не добавлять.
Путь к inventory впоследствии передавать явно через `-i inventories/local/hosts.yml`.

## Порядок реализации

1. Preflight: проверить ОС, исходный доступ и recovery-консоль провайдера.
2. Создать пользователей и проверить новый административный вход по ключу.
3. Настроить SSH и firewall с защитой от потери доступа.
4. Настроить обновления, инструменты разработки, tmux и Claude Code.
5. Добавить опциональный Docker для сервисов под управлением администратора.
6. Добавить lint, syntax checks и проверки итогового состояния и идемпотентности.

До подтверждения нового входа не закрывать исходную SSH-сессию. Реальные изменения
на VPS выполняются только по явному указанию владельца.

## Ограничения

Аккаунт `agent`, tmux и Git worktrees не обеспечивают изоляцию проектов и секретов.
Permission rules Claude не заменяют OS sandbox. tmux сохраняет процессы при
разрыве SSH, но не после перезагрузки. Полностью автономная работа не гарантируется.
Docker-порты требуют отдельной проверки доступности извне: одного UFW недостаточно.
Production-секреты и критичная production-инфраструктура вне scope MVP.

Адрес репозитория: `git@github.com:romamonk/vps-setup.git`.

```sh
git init -b main
git remote add origin git@github.com:romamonk/vps-setup.git
git fetch origin
git branch -r
```

Перед первым коммитом и push проверить существующую удалённую историю;
если репозиторий уже содержит коммиты, сначала согласовать с ней локальные файлы.
