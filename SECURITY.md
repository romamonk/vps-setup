# Безопасность

Реализован базовый Ansible bootstrap Ubuntu 24.04; проверки конкретного VPS
выполняются отдельно. Модель угроз и критерии приёмки описаны в техническом задании.

## Секреты и доступ

- Реальные inventory хранить в `inventories/local/`, исключённом из Git.
- Не коммитить private keys, API/OAuth-токены, пароли и production-секреты.
  `.gitignore` не заменяет просмотр diff перед коммитом.
- Авторизацию Claude выполнять интерактивно; не сохранять токены в логах Ansible.
- Исходный SSH-пароль и sudo-пароль вводить интерактивно из локального терминала.
  `admin` по умолчанию получает sudo без пароля; это осознанная политика для
  администрирования по ключу, она не распространяется на `agent`.
- До изменения SSH/firewall проверить recovery-консоль и вход администратора
  по ключу через отдельное соединение. Сохранять исходную SSH-сессию открытой.

## Границы MVP

- Linux-пользователь не является песочницей: агент имеет доступ ко всем файлам
  и credentials своего аккаунта. tmux и worktrees не изолируют проекты.
- Permission rules Claude не заменяют системную изоляцию.
- `agent` не получает sudo, группу `docker` или доступ к системному Docker socket.
- Docker может публиковать порты в обход ожидаемой политики UFW. Приватные
  сервисы привязывать к loopback и проверять недоступность с внешнего хоста.
- Не подключать критичную production-инфраструктуру и не хранить её секреты на MVP.
- tmux не восстанавливает процессы после reboot; автономная работа ограничена
  подтверждениями, лимитами, сетью и доступностью хоста.

При обнаружении секрета в Git сначала отозвать или заменить его.
Не публиковать действующие credentials в issues или диагностических выводах.
