# Статус требований и полнота реализации

Сверено с кодом репозитория 2026-11-03. Источник требований —
[ТЗ](../VPS_CLAUDE_CODE_BOOTSTRAP_SPEC.md); оно содержит как реализованные,
так и будущие пункты. Рабочий базовый VPS не означает выполнение всех пунктов ТЗ.
Результаты применения — отдельный [исторический протокол](../tests/README.md).

| Область ТЗ | Реализовано | Ограничения и оставшаяся работа |
| --- | --- | --- |
| Preflight | Ubuntu 24.04, имена, наличие ключей, порт; в harden CIDR и флаг recovery | Консоль и fingerprint проверяет владелец; новая ОС и свежая VM не тестировались |
| Исходный доступ | Bootstrap через исходного root/sudo-пользователя; затем ключевые проверки | Парольный SSH-вход и sudo с паролем документированы, но не проверены на VM |
| Пользователи | admin с sudo, agent без дополнительных групп, публичные ключи, home `0700` | Нет миграции существующих home/имён, автоматического отзыва ключей и очистки сторонних sudoers |
| Проверка admin | Свежий вход по ключу в bootstrap; sudo проверяется в configure/harden | Один bootstrap не доказывает работоспособность sudo нового admin |
| SSH | Drop-in, ранний Include, синтаксис, эффективные значения, запрет root/паролей | Match проверяется для текущего клиента; нет миграции порта или теста всех возможных политик |
| Защита от lockout | Ключевые входы до/после reload и UFW; rescue SSH-блока | Rescue зависит от доступности соединения, UFW не откатывается автоматически; recovery обязателен |
| Firewall | UFW, явные CIDR для SSH и дополнительные TCP-порты | Старые разрешения сохраняются; нет управления provider firewall и UDP |
| Обновления | APT safe upgrade при configure; ежедневные security updates, без auto reboot | Службы могут перезапускаться; reboot запускается отдельно |
| fail2ban | sshd jail, systemd backend, проверка статуса | Фактическая блокировка тестового клиента не проверялась |
| Окружение | Базовые CLI, workspace, tmux; опциональные пакеты Go/Python/Node | Опциональные toolchains на VPS не включались и отдельно не тестировались |
| Claude Code | Проверенный установщик, установка под agent, проверка версии | Авторизация и работа над тестовым проектом владельцем ещё не подтверждены |
| Docker/Compose | Защита от выдачи agent доступа к стандартному socket | Docker, Compose-примеры и реальные контейнеры отсутствуют; этап остаётся опциональным |
| Эксплуатация | SSH aliases, tmux, диагностика, отдельный reboot, описание recovery | Нет backup-сервиса, восстановления данных и автозапуска задач после reboot |
| Тесты | Локальные lint/syntax, verify, повторный прогон `changed=0`, reboot, tmux, выборочная проверка портов | Нет Molecule/VM suite, полного внешнего скана, проверки IPv6 и аварийного отката |
| CI | Workflow lint/syntax на push/PR | Не является integration-тестом; результат конкретного запуска проверяется в GitHub Actions |

## Что считать завершённым

Базовый сценарий с исходным ключевым доступом на Ubuntu 24.04 применён и
проверен на одном VPS. Инструкция повторного запуска, параметры и ограничения
описаны в README и [справочнике inventory](inventory.md).

Для полного подтверждения требований нужны отдельные проверки парольного
bootstrap, sudo с паролем, аварийного восстановления и авторизованного Claude.
Для использования Docker или внешнего backup потребуется реализация этих
опциональных подсистем, а не только дополнение текста документации.

Автономная работа без подтверждений, sandbox Claude, rootless Docker, Tailscale,
TLS/reverse proxy и автоматическое создание VPS не включены в текущую реализацию.
Не использовать этот шаблон как универсальную миграцию уже нагруженного сервера.
